# Library and release audit — September 6, 2026

The audit covered the engine, provider clients, checkout and fulfillment services, persistence constraints, jobs, controllers, tests, dependency resolution, documentation and gem packaging. Changes are split into local commits. No tag, push, publication or repository-setting change was made.

The package is ready for an alpha release rehearsal. A clean runtime audit and synthetic tests do not establish production readiness: provider-account checks, publisher setup and the repository controls below remain necessary.

## Fixed findings

| Finding | Change and evidence |
| --- | --- |
| Net::HTTP could retry DELETE outside the operation history | Disabled transport retries; a cancellation transport test checks the configured connection before dispatch. |
| JSON prices passed through floating point | Parse decimals as `BigDecimal`; a long fractional price now retains its original value. |
| Rotating an OAuth secret reused a cached token | Cache identity now includes a digest of both credentials; the rotation test observes a fresh token request. |
| Quotes could use another store's connection or outlive their session | Enforce store/connection identity, include remote Checkout configuration in context, invalidate cache on connection changes, and bound reuse by session expiry. |
| A stale worker could reclaim a rejected operation revision | Rejected revisions cannot be claimed again; corrected retries use a new revision. |
| A worker could die during cancellation while the fulfillment still said `booked` | Reconciliation checks unresolved cancellations before the booked-state shortcut and verifies the provider shipment ID. |
| Booking reconciliation could turn a remotely canceled shipment into `booked` | Preserve cancellation status and record successful reconciliation time. |
| JSON format alone disabled CSRF checks | Exempt only a matching order token; test normal token access and a bogus token with CSRF protection enabled. |
| Admin permissions were checked only against model classes | Scope list queries and authorize individual records, including a connection's proposed store assignment. |
| Tests could reach live nShift endpoints | Enable WebMock globally and deny outbound connections. Reloaded tracking objects use explicit test doubles. |
| Tracking imports could operate on stale fulfillment state and load all event rows | Serialize local imports under a row lock and select status priority in SQL, preserving timestamp tie-breaking. |
| Fractional status IDs could be truncated into valid statuses | Reject non-integral IDs before mapping them. |
| The fallback cache retained unread expired keys indefinitely | Prune expired entries under pressure and cap stored entries at 1,000. |
| Core-only eager loading depended on the undeclared legacy backend | Move controllers/views into Solidus's optional backend directories and omit backend routes when it is absent. |
| Notifications could contain provider exception messages; logger failures could affect bookings | Publish only supplied metadata and error classes, avoid echoing provider error text, and isolate observer failures. |
| Finalization could enqueue a job before its intent committed | Defer enqueueing until all order transactions commit; rollback and commit tests use real transaction boundaries. |
| The default test bundle used a moving Solidus branch and older Rails | Use published Solidus 4.7/Rails 8.1 by default, update audit lockfiles, retain an explicit legacy compatibility job, and require Active Record 7.2 for transaction callbacks. |
| Fresh dummy apps lacked backend asset manifest entries | Add the required assets after dummy generation; verify rendered controllers in Linux/MySQL tests. |
| Release checks stopped at gem creation | Add package contents/metadata verification, a core-only boot check, and runtime auditing before the publish step. |
| Documentation overstated certification, runtime guarantees and repository protections | Rewrite setup/recovery guidance, shorten the architecture guide, and distinguish verified checks from remaining work. |

## Remaining release and production work

1. **Development dependency advisories:** the released `solidus_dev_support` constrains Puma to an affected 6.x version. The runtime package does not depend on Puma. See [SECURITY.md](../SECURITY.md) for the two advisories and the development-server restriction. CI reports this separately; no advisory IDs are suppressed.
2. **Repository controls:** read-only GitHub checks found active immutable-tag, branch-history and PR-review rulesets. They did not find required CI status checks. The PR-review ruleset allows a maintainer bypass, and the release environment permits self-review. Decide and configure the intended approval policy before publishing; rerun the read-only checks in the [release guide](releasing.md). Repository visibility was not changed.
3. **RubyGems setup:** trusted/pending publisher configuration was not verified through an authenticated RubyGems account. Verify the owner, repository, workflow and environment before creating a release tag.
4. **nShift account evidence:** no real account, service mapping, label printout, EDI/test-mode behavior or mutation recovery was certified. Complete the [test-account checklist](sandbox-certification.md). Synthetic contract fixtures cannot replace that check.

## Follow-up improvements

These are separate product or operational choices, not claims that the current tests cover them:

- Move the remaining English admin labels and notices into locale files when supporting translated admin interfaces. Checkout language configuration is already separate.
- Add a `solidus_admin` interface if the target stores use the modern admin; the current UI integrates with `solidus_backend` only.
- Measure simultaneous checkout traffic before adding shared-cache request coalescing. Token locking currently coordinates callers of one provider instance, not all processes or separately constructed providers.
- Define retention/archival policies for old quotes, events and operation errors in the host application. Automatic deletion could remove reconciliation evidence and should not be guessed by this gem.
- Keep custom parcel-builder/transport exceptions free of secrets. Their error messages may be stored in operation history or by the host job backend even though request notifications omit them.
